## 3. Decisão técnica corrigida em relação ao plano

O plano previa implementar o SSE do **web** com `fetch` + `ReadableStream`
manual (o endpoint é `POST`, então `EventSource` não serve). Ao inspecionar o
fonte do Ktor 3.0.3
(`ktor-client/ktor-client-core/wasmJs/.../browser/BrowserFetch.kt`), o engine
wasm **já faz isso**:

```kotlin
internal fun CoroutineScope.channelFromStream(stream: ReadableStream<Uint8Array?>) =
    writer {
        val reader = stream.getReader()
        while (true) {
            val chunk = reader.readChunk() ?: break
            channel.writeFully(chunk.asByteArray())
            channel.flush()          // <- entrega incremental
        }
    }.channel
```

Portanto `bodyAsChannel()` preserva as 2 fases também no Wasm, e **nenhum
código JS específico de plataforma foi necessário**. O risco 1 do plano
(Ktor no wasm) ficou eliminado por evidência de fonte, não por suposição.
